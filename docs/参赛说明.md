# 参赛作品说明 — moon-miniprogram（兔小程序）

> MoonBit 9 月黑客松 · 赛道一（新项目方向）
> 仓库：https://github.com/Magic486/moon-miniprogram
> 包：mooncakes.io → `Magic486/moon-miniprogram@0.2.0`

## 一句话

一套用 MoonBit 编写微信小程序的开发框架：业务逻辑写成纯 MoonBit（类型安全、可单测、可属性测试），构建产物是单个 CommonJS 模块，小程序侧每文件一行装配代码。

## 解决什么问题

| 小程序开发现状 | 本框架 |
|---|---|
| 逻辑与微信全局耦合，只能手点测试 | `moon test` 37 项 + quickcheck 属性测试全绿 |
| `setData` 全量透传，列表越用越卡 | `set_state` 自动 diff，只发变化叶子路径（官方性能建议的自动化） |
| 字符串键、拼写靠记忆 | JSON 桥全链路类型化，`payload.string_at` 等强类型访问器 |
| 业务困在页面闭包，无法复用 | 逻辑是独立库（`yuan` 双向大写金额），mooncakes 发布复用 |

## 技术亮点

1. **diff 引擎（runtime/state.mbt）**：`diff_partial`/`diff_to_paths` 纯函数，根键合并 + 叶子路径展开 + 数组下标级最小补丁 + 删除回退策略，12 组黄金用例。
2. **组件模型（runtime/component.mbt）**：properties 用 JSON 规范描述（`"t":"String"` 在 JS 桥翻译为构造函数，规避 JSON 通道不能传函数），observers 支持，`triggerEvent` 出事件。
3. **带回值钩子（PageDef.returns）**：`onShareAppMessage` 等需要向运行时返回对象的钩子补全。
4. **FFI 边界工程化**：MoonBit 元组跨 FFI 是 `{_0,_1}` 对象 → 平行 FixedArray；`raise` 在 JS 后端是 Result 返回值 → 导出边界显式转译异常；`#export_name` 与 moon test 不兼容 → link exports 按名导出。三条坑全部踩平并写入 AGENTS.md。
5. **无头三层测试**：moon test（37）→ node 模拟微信运行时冒烟（25 断言，含路径感知 setData、组件事件流）→ 开发者工具验收。
6. **生态闭环**：核心库发布 mooncakes，脚手架生成的项目直接 `import "Magic486/moon-miniprogram@0.2.0"` 拉包编译（已实测）。

## 演示步骤（评委/用户）

1. 微信开发者工具（测试号即可）打开 `examples/invoice-helper/` —— 免构建直接运行
2. 首页输入金额 → 实时大写（央行规范）→ 点示例金额筹码（自定义组件）→ 复制 → 历史
3. 无头复现：`moon test`（37/37）→ `powershell scripts/build-example.ps1`（25/25 冒烟）
4. 脚手架体验：`node scripts/new.cjs myapp && cd myapp && moon test`

