# 参赛作品说明 — moon-miniprogram（兔小程序）

> MoonBit 9 月黑客松 · 赛道一（新项目方向 · 完善 MoonBit 生态）
> 仓库：https://github.com/Magic486/moon-miniprogram
> 包：mooncakes.io → `Magic486/moon-miniprogram@0.3.0`

## 一句话

一套用 MoonBit 编写微信小程序的开发框架：业务逻辑写成纯 MoonBit（类型安全、可单测、可属性测试），构建产物是单个 CommonJS 模块，小程序侧每页一行装配代码。**目标：让 MoonBit 生态拥有自己的“小程序 React”。**

## 为什么是生态级项目

MoonBit 是新生语言，缺的是**落地场景**与**生态基建**。微信小程序月活数十亿，其官方开发方式至今没有现代化的类型安全框架（Taro/Remax 属 JS/TS 生态）。本项目用 MoonBit 的 JS 后端，为 MoonBit 补上小程序这个空白——不是“做了一个应用”，而是“给 MoonBit 开发者一条通往微信小程序的路”。

## 技术亮点

1. **setData 自动 diff（性能核心）**：`set_state` 部分合并 + 叶子路径补丁 + 无变化零调用。
   实测：1000 项清单追加 1 项，传输量 34,959 B → **49 B（~713×）**，基准快照进 CI 持续回归。
2. **diff 引擎随机不变式**：200 轮 LCG 可复现的根键收敛性验证，不止手写黄金用例。
3. **组件/页面模型完整**：properties（类型名→构造函数翻译）、observers、pageLifetimes、
   带返回值的钩子（onShareAppMessage）、全局数据、30+ wx API 类型绑定。
4. **可复用无头测试模拟器**（`scripts/sim/wx-sim.js`）：给任何 MoonBit 小程序项目
   端到端测试，App/Page/Component/wx/storage 模拟 + 路径感知 setData + wx 调用记录——
   **其它小程序框架不标配的测试基建**。
5. **脚手架**（`node scripts/new.cjs`）：生成的项目直接从 mooncakes 拉框架编译运行，生态闭环可实测。
6. **FFI 边界工程化**：元组跨 FFI 的表示、`raise`→Result 的异常转译、`#export_name` 与测试的冲突——
   三条新坑踩平并沉淀为 AGENTS.md。

## 测试体系

| 层 | 数量 | 命令 |
|---|---|---|
| 单元测试（diff 黄金用例、桥接、随机不变式、store、路由、平台） | 37 | `moon test` |

全程不需要微信开发者工具即可验证框架正确性。

## 演示步骤（评委）

1. 无头复现：`moon test`（43/43）→ `powershell scripts/build-example.ps1`（38/38 冒烟）
2. 体验脚手架：`node scripts/new.cjs myapp && cd myapp && moon test`
3. `node mmp.cjs dev` 热编译后，微信开发者工具（测试号）打开 `myapp/miniprogram/`，点按钮看界面实时更新
4. 读 README 的性能基准表与架构图
